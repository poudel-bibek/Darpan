# Contributing to Darpan

Thanks for helping. Darpan is a remote desktop that feels local, stays private and costs nothing
while nobody is connected. Bug reports, fixes, new clients and ideas are all welcome.

## Reporting a bug

Open an [issue](../../issues) with:

* what you did, what you expected, and what happened instead;
* your versions: Darpan (`darpan version` on Linux, *About Darpan* on the Mac), Ubuntu, and macOS
  or the browser;
* for problems on the Linux side, the host's log: `journalctl --user -u darpan -u darpan-net -n 200`.

Leave out passwords, addresses and anything else private.

**Security problems:** please don't open an issue. Use
[Report a vulnerability](../../security/advisories/new), so it can be fixed before it's public.

## How the code is laid out

```text
linux/darpan/      host: Python daemon (standard library; PyGObject for its window and the software encoder)
linux/native/      capture and NVENC encoder (C)
linux/web/         browser client, served by the host
linux/packaging/   the .deb and its systemd units
linux/tools/       host and browser tests
mac/               macOS app (Swift)
PROTOCOL.md        wire protocol: the contract every client implements
docs/              the README's animations (generated by docs/*.py)
scripts/           repository checks
dev-messageboard/  the maintainers' working notes (please use issues and pull requests)
```

## Building and testing

* **Linux host:** see [linux/README.md](linux/README.md). `linux/packaging/build-deb.sh` builds the
  package. Tests: `python3 linux/tools/test_host.py` and `node linux/tools/webclient_test.mjs`. They
  start their own virtual display and never touch your desktop.
* **Mac app:** see [mac/README.md](mac/README.md). `mac/build.sh` builds Darpan.app; the tests are
  `swift run SelfTest` in `mac/`.
* **Browser client:** `linux/web/`, covered by the web client test.

## Pull requests

* One change per pull request, with a test when it fixes a bug or adds behavior.
* Keep it simple and surgical. [AGENTS.md](AGENTS.md) has the four rules we work by, and they apply
  to people too.
* Changing what goes over the wire? Update [PROTOCOL.md](PROTOCOL.md) in the same pull request.
* Efficiency is a feature: nothing may run while nobody is connected, and a claim about speed or cost
  needs a measurement.
* Run `scripts/check-private-data.sh` before you commit. It catches e-mail addresses, IP addresses,
  home paths and tailnet names. List your own private terms in `.private-denylist`, which is never
  committed.
* Every pull request gets an automated review and a maintainer's review.
