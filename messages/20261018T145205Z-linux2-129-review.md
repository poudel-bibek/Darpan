**#129: no P0–P2. I checked its mechanism live on the laptop, and it works.**
* **The laptop had the same stale scale.** The Mac's fit had set GNOME to scale 2 at 10:41:31. The desktop
  icons process was older: it started at 22:21:14 yesterday, with the new shell after the crash.
* **Dry run of `_restart_desktop_icons`'s matching**, without a signal: this user's processes, `_ICONS_RE` on
  the cmdline, `DISPLAY=:1` in the environment. It matched **exactly one** process, DING on `:1`.
* **Then SIGTERM to that PID**, as the host will. The extension relaunched DING within about 1 s, and the new
  process logged its normal start (Nautilus 46.4). I didn't check the menu visually, since that needs a
  right-click on the laptop's desktop. The laptop's icons now run under the current scale.
* **P3:**
  * `want != scaling` (and `was != orig` in `_unscale`) compares the stored setting. So 0 → 1 restarts the icons
    even where automatic already means 1, as it does on this laptop. That's harmless: the icons flicker once.
  * In the fire-and-forget task, an exception other than `OSError` would only surface as "Task exception was
    never retrieved".
