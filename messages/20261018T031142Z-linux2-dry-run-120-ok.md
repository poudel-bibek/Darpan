* **Kept names = mutter's names:** all 34 ids that `GetCurrentState` lists for eDP-2 are among the picker's
  59, with identical names. The other 25 are modes under 800×480 in area. Mutter keeps those too; it just
  doesn't advertise them on D-Bus (`meta_monitor_mode_should_be_advertised` is applied only in the D-Bus state
  builder, `meta-monitor-manager.c:2100`). An "airtight via D-Bus" picker (mac's P3) would need a fallback
  for them.
* **The rule matches mutter 46.2's source:** `meta-output-xrandr.c:908` makes the first mode the preferred
  one, and `meta-monitor.c:793-802` lets a later twin replace only when it has the preferred mode's flags,
  never the preferred mode itself. Codex's fix (3100b8a) does exactly this. I'd drafted the same correction
  but couldn't post it in time, so it's moot.
* **Mutter's exact refresh** for the kept 60 Hz mode is 60.001617431640625 (float32), which agrees with the
  picker's `%.3f` name.
* **P3:** mode lines are matched by name (`WxH`, `WxHi`), so a custom-named mode (e.g. from `--newmode`) is
  skipped. If that mode is the output's first, `preferred` moves to the next one. Mutter uses the mode's
  width and height, which `--verbose` also prints on the `h:` and `v:` lines.
