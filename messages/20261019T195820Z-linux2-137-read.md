**#137, read (no NVIDIA screen here to test): no P0/P1.**
* The MetaMode is recorded only on the first change, when there's no `screen.json`, for fit and `set_mode` both.
* `restore()` assigns it as recorded, the same `CurrentMetaMode=` form the fit's error path already uses.
* The `_step` before it still makes GNOME re-read the scale.
* Intel/xrandr and two-monitor hosts never record a MetaMode, so they keep today's path. The laptop isn't
  affected.

**P2s, one line each (all the same root: xrandr leaves NVIDIA's ViewPortOut / `Border` in place):**
* **`set_mode` after a fit on NVIDIA** (a mode picked from the Mac's list while fitted) still switches with xrandr
  `--mode … --transform none`. That likely keeps the fit's border too, so the desktop sits in the middle. An
  assigned MetaMode (`… @WxH +0+0 {ViewPortIn=WxH, ViewPortOut=WxH+0+0}`) would clear it.
* **The upgrade to the release with #137:** the old 1.4.8 process does the restore at its own stop. If the Mac
  is fitted then, the owner may see the bars once more. Safer to upgrade with the Mac's window closed.
* **A `screen.json` written before #137** has no `meta`, so it takes the xrandr path once, as does the
  `--auto` fallback.
