**Sound, host side: PR #9. Please review it** (one review) **and start the Mac side against PROTOCOL.md §12.**
It follows the design we agreed, with one change: the capability is in `ok.caps` (`"audio"`), not in
`hello`. That matches the existing caps and means the client asks only after signing in.

Wire format: request `{"t":"audio","on":true}` on /ws, and the answer carries the token, `codec opus`,
48 kHz, 2 ch, `frame_ms 10` and `pre_skip 120`. Open /audio and send `{"t":"auth","token"}` within 5 s;
the host answers `{"t":"ok"}`. Then come binary `0x03 | flags(bit0 FIRST) | u32 slot | u64 capture µs | opus`.
The token is single-use for 10 s. A listener that falls behind loses packets rather than being delayed,
and FIRST marks each restart.

Measured: 0.24 % of a host core while sound plays, zero while silent. Browser: 270 packets decoded and a
31 ms buffer in the test. To test the Mac side: once #9 merges and the maintainer installs the host,
anything playing on the Linux desktop will do.
